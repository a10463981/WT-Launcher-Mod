# 05 · 用模拟器验证（PVE + Android-x86 4.4）

> 目的：在不动真车的前提下，验证改过的 dex 能不能加载、白名单是否生效、图标是否正确。

---

## 一、PVE 建虚拟机

| 项 | 值 | 说明 |
|---|---|---|
| 机型 | **i440fx** | q35 对 4.4 内核不友好 |
| BIOS | **SeaBIOS** | 4.4 只支持传统 BIOS |
| 显示 | **VGA (std)** | 没有 virtio-gpu 驱动 |
| 磁盘 | **SATA**，16 GB | VirtIO SCSI 驱动缺失 |
| 内存 | 4096 MB | |
| CPU | 2 核，类型 host | |
| 网络 | vmbr0，模型 **Intel E1000** | VirtIO 网卡不稳 |

安装：

1. 启动菜单选 `Installation - Install Android-x86 to harddisk`
2. 分区：**MBR（DOS）分区表** + 一个主分区用满全盘 + Bootable 标志
   > 用 GPT 会报 **SeaBIOS Error 17**（找不到可引导记录）
3. 格式化选 **ext3**（这个版本没有 ext4 选项）
4. `/system` 选 **read-write**
5. **GRUB 必须选 Yes**（默认是 Skip，跳过就引导不了）
6. EFI GRUB2 选 Skip（我们是 BIOS 启动）
7. 装完卸载 ISO，硬盘优先启动

## 二、跳过初始化向导

首次启动会卡在"网络"那一步白屏（向导要连 Google）。

```bash
# PVE noVNC：左侧「Send key」→ Ctrl+Alt+F1
pm disable com.google.android.setupwizard
pm disable com.android.provision
am start -a android.intent.action.MAIN -c android.intent.category.HOME
# 切回图形：Send key → Ctrl+Alt+F7
```

或在 GRUB 里给内核行加 `SETUPWIZARD=0`。

## 三、开 ADB

```bash
# 虚拟机内（Alt+F1）
setprop persist.adb.tcp.port 5555
stop adbd
start adbd
ifconfig eth0          # 看 IP
```

```bash
# 宿主机
adb connect <IP>:5555
adb devices
```

## 四、安装测试版桌面

真车 APK 带 `sharedUserId=android.uid.system`，模拟器签名不匹配装不上。做一份**去掉 sharedUserId** 的测试版：

```bash
apktool d -f WT_Launcher_patch.apk -o test
sed -i 's/ android:sharedUserId="android.uid.system"//' test/AndroidManifest.xml
apktool b test -o test.apk
zipalign -f 4 test.apk test-aligned.apk
apksigner sign --ks my.jks --min-sdk-version 19 \
  --v1-signing-enabled true --v2-signing-enabled false \
  --out test-signed.apk test-aligned.apk

adb install -r test-signed.apk
adb logcat -c
adb shell am start -n com.android.launcherWT/com.android.launcherWT.MainActivity
adb logcat -d | grep -E "FATAL|Caused by|AppInfo"
```

**注意**：dex 是同一个，只改了 manifest 一行，所以代码验证结论对真车有效。

## 五、模拟车机屏幕比例（关键）

CS75 PLUS 中控是 **12.3 英寸 1920×720（8:3）**，模拟器默认 800×600（4:3）会让布局完全失真。

```bash
# 逻辑分辨率设成 8:3（1280×480 正好是 1920×720 的 2/3）
adb shell wm size 1280x480
adb shell wm density 240

# 确认
adb shell dumpsys window displays | grep -E "init=|cur="
```

效果：桌面变成 5 列布局，和车机一致。

> `wm size` 重启失效，每次开机重新执行。
> 上下黑边是 QEMU 物理面板（800×600）造成的，不影响布局调试。

## 六、验证清单

| 检查 | 方法 | 期望 |
|---|---|---|
| dex 能加载 | `dumpsys window \| grep mCurrentFocus` | 焦点是 `com.android.launcherWT/...MainActivity` |
| 没有崩溃 | `logcat \| grep FATAL` | 无输出 |
| 白名单生效 | `logcat \| grep "setNewData"` | `appInfo.size()` = 已安装的白名单应用数 |
| 顺序正确 | `logcat \| grep "getItem: appInfo"` | 按白名单顺序 |
| 图标正确 | `logcat \| grep "getAppIconResourcesId: [0-9]"` | 返回非 0 的资源 ID |

## 七、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 开机黑屏 | 显示不是 VGA std | 改显示设备 |
| `Error 17` | GPT 分区表 | 用 fdisk `o` 重建 MBR |
| 装不上 APK | 签名冲突 | 先 `pm uninstall` |
| `INSTALL_FAILED_SHARED_USER_INCOMPATIBLE` | sharedUserId | 去掉该属性重新签名 |
| 没网 | VirtIO 网卡 | 改 Intel E1000 |
| 卡向导 | 连不上 Google | `pm disable` 两个包 |

## 八、车机屏幕尺寸的确凿证据

不用猜，桌面资源里就有答案：

| 资源 | 尺寸 |
|---|---|
| `res/drawable/classic_bg.jpg` | **1920×720** |
| `res/drawable/simple_bg.png` | **1920×720** |
| `res/drawable/sport_bg.png` | **1920×720** |
| `res/drawable-land-hdpi-v4/ic_common_bg.jpg` | **1920×720** |
| `res/drawable-hdpi-v4/launch_bg.png` | 1776×720 |
| 全部图标 | `drawable-land-hdpi-v4` → 密度 **240dpi（hdpi）** |

**结论：车机屏幕 1920×720 px / 240dpi → dp 画布 1280×480（8:3）。**

### 模拟器等效设置

```bash
adb shell wm size 1280x480     # 正好是 1920×720 的 2/3
adb shell wm density 240
```

这样做出来的布局（5 列网格、136px 图标、间距）与车机 1:1 等效。

### 为什么模拟器有黑边（无解）

QEMU 标准 VGA + uvesafb 只认 BIOS 里的标准 VESA 模式（800×600 / 1024×768 / 1920×1080 …），**没有 8:3**。
以下尝试均失败：

| 尝试 | 结果 |
|---|---|
| 内核参数 `video=1920x1080` | 写入 cmdline 但被忽略 |
| 内核参数 `video=1920x720` | VESA 没有该模式 |
| `init.sh` 里 `UVESA_MODE=1920x720` | uvesafb 拒绝，回退 800×600 |
| `init.sh` 里 `UVESA_MODE=1280x720` | 同样拒绝 |
| 写 `/sys/class/graphics/fb0/mode` | 只读，无效 |

**要真 8:3 无黑边，只能用 Android-x86 9.0 + VirtIO-GPU**（支持 `xres=1920,yres=720`）。
否则接受黑边——逻辑布局仍然是对的。
