# 04 · 避坑指南：黑屏的四个真实原因

> 这些坑都是实测踩出来的，不是推测。按出现概率排序。

---

## 坑 1 · `AppInfo` 的 NPE（最常见的黑屏）

### 位置

`com/autopai/applist/model/infos/AppInfo.smali`，4 参构造：

```java
public AppInfo(Context context, long id, String label, String packageName) {
    ...
    String name = AppIconManager.getAppIconResourcesId(packageName, null);
    int resourcesID = Utilities.getResourcesID(context, name, "drawable");
    if (resourcesID > 0) {
        this.iconDrawable = context.getResources().getDrawable(resourcesID);
    } else {
        this.iconDrawable = this.mInfo.getBadgedIcon(240);   // ← mInfo 恒为 null
    }
}
```

这个构造函数里 `mInfo` **永远是 null**（它只被 `initData()` 用来造占位项）。
原版 15 个应用都有内置图标，永远走 `if` 分支；**你新加的应用如果没有图标映射，就会走 `else` → NPE → 桌面 inflate 失败 → 黑屏**。

### 修复

把 `else` 分支改成直接置空，不要调用 `mInfo`：

```diff
-    :cond_1
-    iget-object v3, p0, ...AppInfo;->mInfo:...;
-    if-nez v3, :cond_0
-    const/16 v4, 0xf0
-    invoke-virtual {v3, v4}, ...LauncherActivityInfoCompat;->getBadgedIcon(I)Landroid/graphics/drawable/Drawable;
-    move-result-object v3
-    iput-object v3, p0, ...AppInfo;->iconDrawable:Landroid/graphics/drawable/Drawable;
-    goto :goto_0
+    :cond_1
+    const/4 v3, 0x0
+    iput-object v3, p0, ...AppInfo;->iconDrawable:Landroid/graphics/drawable/Drawable;
+    goto :goto_0
```

> ⚠️ 只加 `if-nez` 判断**不保险**——实测仍然会崩。直接把调用去掉最稳。

## 坑 2 · `getResourcesID` 空名字 NPE（主题切换时）

`Utilities.getResourcesID()` 直接调用 `Resources.getIdentifier(name, ...)`，
而 AOSP 的 `getIdentifier` 在 `name == null` 时**主动抛 NPE**。

什么时候 `name` 是 null？当车型主题不是 classic 时，`AppIconManager.getIcons()` 返回的是
`sport` / `simple` 的 map，里面**没有你新加的包** → `map.get()` 返回 null。

### 修复

在方法开头加空判断（注意方向！）：

```smali
.method public static getResourcesID(Landroid/content/Context;Ljava/lang/String;Ljava/lang/String;)I
    .locals 2
    .param p0, "context"
    .param p1, "idname"
    .param p2, "localxy"

    .prologue
    if-eqz p1, :cond_null_name     # idname == null → 跳到返回 0

    .line 764
    invoke-virtual {p0}, Landroid/content/Context;->getResources()Landroid/content/res/Resources;
    move-result-object v0
    .line 765
    invoke-virtual {p0}, Landroid/content/Context;->getPackageName()Ljava/lang/String;
    move-result-object v1
    invoke-virtual {v0, p1, p2, v1}, Landroid/content/res/Resources;->getIdentifier(Ljava/lang/String;Ljava/lang/String;Ljava/lang/String;)I
    move-result v1
    return v1

    :cond_null_name
    const/4 v0, 0x0
    return v0
.end method
```

### ⚠️ 我们在这里翻过车

第一版写成了：

```smali
if-eqz p1, :cond_name_ok     # 错！null 时反而走正常代码
const/4 v0, 0x0
return v0
:cond_name_ok
```

结果 **所有应用的内置图标全部查不到**（`getIdentifier` 永远返回 0），
桌面变成清一色的"应用自带大图标"。

用 `dexdump -d` 可以确认反了：

```
0000: if-eqz v3, 0004    ← null 时跳到正常代码
0002: const/4 v0, 0
0003: return v0          ← 非 null 时返回 0（错误）
```

**改完务必 dump 出来看一遍。**

## 坑 3 · `sharedUserId=android.uid.system` 与签名

桌面 APK 声明了：

```xml
android:sharedUserId="android.uid.system"
```

这意味着：

- **在模拟器里装不上**：模拟器的平台签名（Android-x86 / AOSP testkey）和车机的不同
  → `INSTALL_FAILED_SHARED_USER_INCOMPATIBLE`；
- **放进 `/system/app` 也无效**：PackageManager 扫描时因共享 UID 签名不符直接跳过，logcat 会有
  `has no signatures that match those in shared user android.uid.system`。

### 结论

- **模拟器验证代码**：去掉 `sharedUserId` 再用自己的 key 签名，可以正常跑；
- **真车安装**：保留原样（原厂签名没动），系统认得。

### 两种签名策略

| 策略 | 做法 | 适用 |
|---|---|---|
| **保留原签名**（推荐） | 只替换 `classes.dex` 和 PNG，`META-INF` 一个字节不动 | 和"大图标版"同款，原厂验证过 |
| 重签（同序列号） | 用与平台证书**相同序列号**的自签证书重签 | 类似 52pojie 的 CertificateManager 绕过思路 |

> PackageManager 在 Android 4.4 上只校验 `MANIFEST.MF / CERT.SF / CERT.RSA` 链，
> **不逐条校验 entry 摘要**，所以"改了内容但保留旧签名"是可行的。

## 坑 4 · 打包细节

| 细节 | 说明 |
|---|---|
| **不要用 apktool 重建资源** | 只替换 dex 和 PNG 用 zip 操作，`resources.arsc` 保持原样 |
| **PNG 要 STORED** | 原 APK 里图标是未压缩存储，替换后要保持 `compress_type=0` |
| **必须 zipalign** | `zipalign -f 4`，否则 4 字节对齐失败可能加载异常 |
| **META-INF 不要动** | 动了签名就废 |
| **dex 用 apktool 重建** | 只重建 dex 是安全的（`apktool d` → 改 smali → `apktool b` → 取出 `classes.dex`） |

### 正确的打包顺序

```
原 APK
 ├─ classes.dex      ← 用 apktool 重建后的（含补丁）
 ├─ res/*.png        ← 要替换的图标
 └─ META-INF/*       ← 原封不动
        ↓ zip 重打包
     zipalign -f 4
        ↓
     成品 APK（未重签）
```

## 坑 5 · 主题（classic / sport / simple）

`AppsConfig` 有三套图标 map：

```java
mClassicConfigAppMap   // 主题 0
mSportConfigAppMap     // 主题 1
mSimpleConfigAppMap    // 主题 2
```

白名单过滤只用 **classic** 的 key，但**图标**用当前主题的 map。

所以：如果车机用的是 sport/simple 主题，你的新包在图标 map 里不存在 → 图标回落应用自带（大图）。

**解决**：要么保证车机用 classic 主题，要么把新包同时加到 `AppsConfig$2`（sport）和 `$3`（simple）。

## 坑 6 · 验证顺序（血泪）

1. **先反编译确认偏移**：不同固件版本的行号/字段不同，别照抄；
2. **用模拟器验证 dex**：Android-x86 4.4 + 去掉 `sharedUserId`（见 [05](05-模拟器验证.md)）；
3. **看 logcat**：`FATAL EXCEPTION` 的第一行 `Caused by` 就是答案；
4. **最后才上车**，并且**先备份** `/system/app/WT_Launcher.apk`。
